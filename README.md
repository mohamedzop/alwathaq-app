# الوثاق للصرافة — تطبيق واحد متكامل

الموقع العام + بوابة الموظفين الداخلية + قاعدة البيانات في **مشروع واحد وخادم واحد ورابط واحد**، كما اتفقنا:

- **الموقع العام** → `/` و `/about` و `/services` و `/contact` (ملفات `site/` — التصميم نفسه ما تغيّر).
- **بوابة الموظفين** → `/portal` (محمية بتسجيل دخول حقيقي، لا تظهر في قوائم الموقع العام — رابط «دخول الموظفين» يظهر في أسفل الصفحة فقط عندما يقدّم هذا الخادم الصفحة).
  - صفحات المدير: لوحة اليوم · المعاملات · العملاء · التقارير · **إقفال اليوم (جرد نقدي)** · **الأسعار (إدارة التحديث)** · المستخدمون.
- **قاعدة البيانات** → SQLite: العملاء، المعاملات، المستخدمين، إقفال اليوم/الجرد النقدي (`cash_days` + `cash_adjustments`) (انظر `DATABASE.md`).

> ميزة مهمة: **بلا أي اعتماديات خارجية** — لا يحتاج `npm install`. يعمل بأدوات Node المدمجة فقط (`node:sqlite` وغيرها).

## التشغيل محلياً
```bash
node server.js
```
ثم افتح:
- الموقع العام: http://localhost:8123
- بوابة الموظفين: http://localhost:8123/portal

**حسابات البداية** (تظهر أيضاً في نافذة الخادم عند أول تشغيل — غيّرها فوراً من صفحة «المستخدمون»):
| الدور | اسم المستخدم | كلمة المرور |
|---|---|---|
| مدير | `admin` | `admin123` |
| موظف | `employee` | `emp123` |

## النشر — موقع واحد يدعم الخادم وقاعدة بيانات (بدل GitHub Pages)

GitHub Pages لا يشغّل قاعدة بيانات، لذا لنشر «الموقع الواحد» استخدم منصة تدعم Node (Render أو Railway).
أغلب الإعداد جاهز في الملفات `render.yaml` و `Dockerfile` و `railway.json`.

> **السر المهم**: قاعدة البيانات تُخزَّن على **قرص دائم**، لا داخل صورة التطبيق.
> الخادم يقرأ مسار القاعدة من متغير البيئة `DB_PATH` (الافتراضي هو `/data/alwathaq.db`).
> الجلسات (تسجيل الدخول) في الذاكرة — كل إعادة نشر/تشغيل تُلزم الجميع بتسجيل الدخول من جديد، وهذا مقصود.

### الخيار أ — Render (الأسهل)
1. ارفع مجلد `alwathaq-site` كاملاً إلى مستودع GitHub.
2. في Render: **New > Blueprint** واختر المستودع.
   - سيقرأ `render.yaml` تلقائياً (قرص دائم `/data`، فحص صحي `/api/health`، أمر التشغيل `node server.js`).
3. اضغط **Apply** وانتظر — ثم افتح الرابط `https://alwathaq.onrender.com`.

أو يدوياً: **New > Web Service** واربط المستودع، وحدد:
- Build command: `true` (لا اعتماديات) — Start command: `node server.js`
- **Persistent Disk** → مسار `/data` (حجم 1GB مثلاً) — متغير `DB_PATH=/data/alwathaq.db`

### الخيار ب — Railway
1. ارفع المجلد إلى مستودع GitHub واربطه بموقع Railway (سيكتشف `railway.json` + `Dockerfile` تلقائياً).
2. أضف متغير `DB_PATH=/data/alwathaq.db`.
3. اربط **Volume** بمسار `/data` من تبويب الخدمة (Settings → Volumes).
4. Deploy — ثم افتح رابط الخدمة الذي يوفّره Railway.

### بعد النشر (خطوة أمان إلزامية)
- غيّر كلمة مرور `admin` و `employee` فوراً من صفحة **المستخدمون** في `/portal`.
- إن كانت بيانات تجريبية من `seed-demo.mjs` غير مطلوبة، امسحها من «المعاملات/العملاء».
- استخدم الرابط الرسمي (`onrender.com` / `up.railway.app`) النهائي وليس رقمياً محلياً، وحدّث روابط واتساب/خريطة في الموقع إن لزم.

## أسعار الصرف — تحرير مباشر من بوابة الموظفين (بدون Google Sheets)
الأسعار تُحرَّر **داخل بوابة الموظفين مباشرة** — لا حاجة لفتح جدول الشركة أو تعديل أي كود:

- صفحة «الأسعار» في `/portal` (متاحة لأي موظف مخوّل): جدول قابل للتعديل بكل الأسعار (قطاعي/جملة) وزر **💾 حفظ** — التعديل يظهر فوراً في الموقع العام والحاسبة عبر `GET /api/rates` (عام، بلا مصادقة).
- قاعدة البيانات (`rates`) هي المصدر الأساسي؛ تُزرع الأسعار أول مرة تلقائياً (من الجدول إن وُصل إليه، وإلا من قيم احتياطية).
- جدول الشركة اختياري الآن: زر «⬇ استيراد من جدول الشركة» (مدير فقط — `POST /api/rates/import`) يجلب كل أسعار الجدول دفعة واحدة ويستبدل الحالية. غيّر الجدول من متغير `RATES_SHEET_ID`.
- جدول الأسعار المتوقع (الصف الأول عناوين، عند الاستيراد):
  ```
  key,retail,wholesale
  USD_cash,9.285,9.270
  EUR_bank,10.30,10.20
  VODAFONE_cash,1.00,1.00
  ```
  المفاتيح: `USD` / `EUR` / `VODAFONE` مع `_cash` / `_bank` / `_card` (حسب ما يحتاجه الموقع).
- الموقع العام يفضّل `/api/rates`؛ فإن تعذّر (مثلاً نسخة ثابتة على GitHub Pages) يرجع تلقائياً لطريقة JSONP القديمة، ثم للأسعار الاحتياطية في `site/rates.js` (احتياطية فقط).

## أدوات المطوّر (اختيارية)
- `node test-api.mjs` — 33 اختباراً تلقائياً للمصادقة والصلاحيات والبيانات والأسعار (الخادم يجب أن يكون شغالاً).
- `node seed-demo.mjs` — يعيد ضبط بيانات تجريبية واقعية (أوقف الخادم أولاً).
- بيانات حقيقية للنسخة المنشورة: عدّل كلمات المرور من صفحة «المستخدمون»، وامسح بيانات التجربة من «المعاملات/العملاء» أو أعد التهيئة.

## البنية
```
alwathaq-site/
├── server.js            # الخادم + قاعدة البيانات + API (بدون اعتماديات)
├── package.json
├── site/                # الموقع العام (HTML/CSS/JS/صور)
├── portal/              # بوابة الموظفين (index.html / portal.css / app.js)
├── data/alwathaq.db     # تُنشأ تلقائياً عند أول تشغيل
├── DATABASE.md          # تصميم قاعدة البيانات
└── seed-demo.mjs        # بيانات تجريبية
```

## ملاحظة قانونية
نظراً لأن طلب الترخيص من مصرف ليبيا المركزي لا يزال قيد الإجراء، البوابة الداخلية أداة **تنظيم داخلي فقط** (سجلاتكم الخاصة) ولا تُعرض للعامة — ولا يوجد في الموقع العام أي ما يوحي بترخيص غير مؤكد.
